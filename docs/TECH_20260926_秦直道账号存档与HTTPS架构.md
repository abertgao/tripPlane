## 二、架构决策

### 单机、同源、三个边界

1. **浏览器**：React18 + Vite + 现有Tailwind/Remix Icon；共享Zod模型；IndexedDB管理本地旅程、离线操作队列和检查点。
2. **同源HTTPS入口**：Nginx提供版本化静态构建及 `/api/v1/` 反向代理。后端仅回环监听，公网只开放必要入口。
3. **应用服务**：Node22 + Express5 + SQLite（优先维护成熟的 `better-sqlite3` 驱动，依赖锁定并测试原生模块）；一个systemd服务，无Redis/队列集群/容器平台的必要性。

SQLite用于少量用户、短事务的结构化状态；数据库每个事务内完成归属、版本和幂等检查。不把文件目录名当用户授权。性能达到边界再考虑PostgreSQL，而不是现在先建设大规模架构。

AI适配器是服务端模块，不直接暴露厂商接口或把密钥放浏览器。不配置模型时关闭能力，其余功能完全可用。

### 拟新增/复用模块

| `src/app/` | 新应用壳、页面、React组件，渐进接替 `src/qin/main.js` |

| `src/features/saves/` | IndexedDB、命名空间、检查点、导入导出、同步 |

## 三、共享业务数据契约

所有外部输入经Zod严格DTO验证，禁止任意对象、任意键写入、客户端提供owner/role。对导入数据、数据库旧记录、模型输出、第三方地理信息分别校验，不能只在表单验证一次。

### 地点与章节

- `ContentPack`：稳定ID、版本、展示名、适用区域和可用故事集合。首版只有本次行程内容包，不硬编码秦直道为产品或所有旅程的默认内容。
- `Theme`：经服务端校验的主题ID与名称，首版涵盖遗址与石刻、陶瓷与工艺、寺窟与建筑、古道与交通、博物馆与地方生活、河湖与地貌。一个地点可有多个主题；选择是偏好，不是全主题集齐门槛。
- `StoryArc`：独立地点/合理小区域的故事ID、涉及地点、主题、任务依赖与结局条件。跨区域旅行总叙事引用已完成的地点故事，不要求秦直道线索作为前置条件。
- `Place`：内部ID、用户原名、规范名、候选别名、区域、受控主题ID集合、身份核验状态。
- `AccessInfo`：游客入口、停车点各自信息；坐标系；合法通行/车型要求、短线长度、台阶/坡度；开放/预约状态。
- `EvidenceSource`：可信来源固定链接、发布日、查阅日、适用游览日、支持的事实字段、冲突或过期标记。
- `Quest`：稳定ID、章节ID、Place ID、导航、情景、3–5项行动、NPC反应条件、线索、后继条件和不可用时替代。
- `Clue`：稳定ID、来源任务/来源资料、亲见或资料证据级别、已解锁关联；不依赖数组下标。
- 内容包版本与存档schema版本分开；新文案不直接破坏旧进度，删除/合并任务有明确迁移映射。

### 旅程与用户记录

- `Journey`：服务器生成UUID、用户归属、名称、起止日、内容包版本、schema版本、revision、更新时间、删除墓碑。
- `JourneyState`：已选择/计划/跳过地点、当前任务、行动勾选、已获线索、个人选择、有限长度文本笔记、每日日程、剧情状态。
- `Checkpoint`：所属旅程、版本、原因、创建时间、严格验证的状态快照；恢复之前先留当前快照。
- `Mutation`：CSPRNG生成的幂等ID、旅程ID、baseRevision、固定操作类型与校验payload；不接受任意JSON Patch路径。
- `AIProposal`：所属用户/旅程、生成时revision、结构化修改、所引用Place/Source ID、解释、状态、到期时间。

数据库表：`users`、`invites`、`sessions`、`recovery_codes`、`journeys`、`journey_versions`、`mutation_receipts`、`ai_proposals`、`schema_migrations`。为归属/旅程/版本建立索引与外键。历史版本查询也通过旅程归属联合校验，不能仅按版本ID查询。

首版默认限制可服务端配置：每用户20个旅程；每旅程50个历史检查点；单次导入最大1MiB；固定上限的文本、任务项、数组、嵌套深度；AI单请求每日/并发额度。达到配额清晰拒绝，不能静默删用户手动检查点。

## 四、账号、邀请与授权

### 身份生命周期

- 用户名+口令，不收集身份证、邮箱、手机号等非必要资料。口令长度12–128字符，不截断；使用scrypt带随机盐及版本化参数，常量时间比较。
- 首位管理员通过服务器本地受限命令初始化，口令从安全的环境配置或隐藏输入读取；无默认凭据、无公网首用户自动抢占权限。初始化入口正常运行时不可调用。
- 管理员生成一次性邀请码：CSPRNG、数据库仅存哈希、期限和可用次数；注册事务中检查并消耗，防并发重复使用。
- 邀请信息一次展示且不进入访问日志；不把邀请码放URL查询串，采用注册页手动粘贴。即使拥有邀请码也只能注册普通用户，角色由服务端决定。
- 登录失败给通用错误；按客户端和账号分别限流，避免用户名枚举及全站封锁。CPU密集口令校验控制并发，配置合理scrypt成本。
- 登录生成不透明随机会话，服务端只存哈希；认证cookie采用 `__Host-` 前缀、Secure、HttpOnly、Path=/、SameSite=Lax、不设Domain。
- 会话有闲置/绝对到期，登录和权限变化轮换；退出、停用、口令重置撤销相关会话。
- HTTPS登录前不接受口令；代理来源只信任本机Nginx，客户端伪造 `X-Forwarded-Proto` 不得开启认证。

### 密码恢复与管理

首版无邮件系统：创建账号后一次展示恢复码（仅存哈希）；用户可自行保存。忘记口令时使用恢复码并设置新口令，之后撤销会话并轮换恢复码。管理员也可为已核实身份的同行者生成短时、单次重置凭据，不可查看或替用户生成公开默认密码。

管理员界面提供邀请创建/撤销、用户列表、停用与会话撤销，不默认开放读取私人旅程。最后一位有效管理员不能被普通停用流程删除。管理员敏感操作要求近期验证口令、角色检查与CSRF验证。

### 每次非公开请求

顺序为：体积/格式检查→会话验证→用户有效状态→CSRF（变更请求）→角色/资源归属→版本/业务条件→事务写入。

CSRF使用会话绑定token和精确Origin检查，SameSite只是辅助；登录/注册也做同源Origin检查和滥用防护。默认不启用跨域CORS。响应不回传内部栈、SQL或模型密钥；日志使用请求ID和非敏感错误码。

## 五、本机存档与同步

### 存储分区

- 游客档位于独立guest空间，账号A/B各自命名空间由服务器确认的用户ID确定；绝不让客户端选择owner绕过接口权限。
- 登录不自动上传整个浏览器数据；用户选择“将此游客旅程另存到我的账号”，生成新的服务器归属和ID。
- 本机离线副本不是密码加密保险箱。默认退出删除该账号本机私有副本，先提示未同步更改并允许导出；共享设备不提供持久离线副本选项。
- 个人设备可显式开启“此设备保留离线旅程”；必须说明持有设备的人可能读到缓存，退出/切换账号时界面不展示另一用户内容。服务端会话失效时不能继续网络写入。
- Service Worker只缓存版本化公共应用壳与明确公共内容；`/api/`、登录、邀请、AI和所有用户响应均 `Cache-Control: no-store`，不落CacheStorage。用户离线副本只经受控IndexedDB写入。

### 写入与冲突

1. 本机编辑先经schema和业务规则校验，以事务写入本机状态和待同步队列，显示“已保存本机，待同步”。
2. 同步带固定操作类型、幂等ID、baseRevision。
3. 服务端在短事务内校验所属用户、未删除、版本相等；记录幂等结果、检查点（需要时）、新状态及新revision。
4. 相同幂等ID和相同payload重试返回原结果；同ID不同payload拒绝。会话超时保持本机队列，不无限自动重试。
5. revision不匹配返回409及可访问的当前版本；客户端保留两份，展示差异，允许另存分支或显式选择，不采用最后写入覆盖。
6. 恢复检查点是一次新的变更，不把revision倒退；恢复前保存现态，后续旧队列需重新检查。
7. 删除产生墓碑，不能被离线设备旧更新复活；删除拒绝写入并允许另存新旅程。永久清除历史须明确确认和保留期策略。
8. AI应用与普通编辑同一事务/版本模型，防止两套更新路径绕过冲突检查。

默认采用短间隔合并操作与页面激活同步，不建设WebSocket。客户端有未同步更改时不以云端拉取覆盖本机。存储被禁用/容量满时明确失败且提供导出，不显示保存成功。

### 导入导出

JSON封套包含产品标识、导出schema版本、内容包版本、导出时间、经过选择的旅程数据；**不含密码哈希、cookie、邀请码、恢复码、服务器路径和AI密钥**。

- 先在浏览器检查文件大小、允许扩展名与内容，再按schema校验对象，拒绝额外字段、控制字符、未知操作或过量数组。
- 文件名不参与服务器路径；如需保存导入文件，服务器随机UUID命名、固定私有目录、归一化边界检查，拒绝路径分隔符/双扩展/NUL/驱动器前缀/`..`。
- 原始导入内容经服务端独立校验才可同步。未知Place/Quest ID进入迁移预览，不直接解锁线索。
- 默认新建旅程，保留原档；名称冲突允许改名。新建后的用户归属由服务端设置，不能继承文件中的owner。
- 旧 `qin-route-checks` 仅导入为“旧日程自报完成”；`qin-prep` 为准备清单；`qin-custom-tasks` 为旧自定义备注。没有足够信息时不推断剧情任务/到访证据。

## 六、API 草案

统一JSON、固定DTO、体积上限、通用错误结构 `{code, message, requestId}`。不公开内部异常。以下为契约规划，不是已存在接口。

| 接口 | 权限与行为 |
|---|---|
| `GET /api/v1/health` | 公共，最少状态；不返回环境/密钥/版本细节 |
| `GET /api/v1/capabilities` | 公共，AI/同步能力可用性，不泄露厂商配置 |
| `POST /api/v1/auth/register` | 同源、邀请码、限流，事务消耗邀请码 |
| `POST /api/v1/auth/login` | 同源、账号/IP限流，签发安全cookie |
| `GET /api/v1/auth/session` | 返回当前身份与会话CSRF token，no-store |
| `POST /api/v1/auth/logout` | 认证+CSRF，撤销会话 |
| `POST /api/v1/auth/password` | 认证+CSRF+原口令校验，撤销其他会话 |
| `POST /api/v1/auth/recover` | 单次恢复凭据+同源+限流，重置并撤销会话 |
| `GET/POST /api/v1/journeys` | 仅当前用户列表/新建，不接受owner |
| `GET /api/v1/journeys/:id` | 归属验证，返回revision |
| `POST /api/v1/journeys/:id/mutations` | 归属+CSRF+幂等+baseRevision，固定操作白名单 |
| `POST /api/v1/journeys/:id/checkpoints` | 归属+CSRF+baseRevision，手动命名检查点 |
| `GET /api/v1/journeys/:id/versions` | 归属后列本旅程版本，分页有上限 |
| `POST /api/v1/journeys/:id/restore` | 归属+CSRF+版本从属+baseRevision，原子备份与恢复 |
| `DELETE /api/v1/journeys/:id` | 归属+CSRF+baseRevision+幂等，墓碑 |
| `POST /api/v1/journeys/:id/ai/proposals` | 认证+CSRF+归属+额度，返回结构化提案或明确503未配置 |
| `POST /api/v1/journeys/:id/ai/proposals/:proposalId/apply` | 同时验证提案与旅程归属、revision、有效期、幂等；原子应用 |
| `GET/POST /api/v1/admin/invites` | 管理员；创建需要CSRF与近期再验证 |
| `POST /api/v1/admin/invites/:id/revoke` | 管理员+CSRF+近期再验证 |
| `GET /api/v1/admin/users` | 管理员，只提供必要账户管理字段 |
| `POST /api/v1/admin/users/:id/status` | 管理员+CSRF+近期再验证，防最后管理员锁死 |
| `POST /api/v1/admin/users/:id/reset-grant` | 管理员+CSRF+近期再验证，单次短时凭据 |

会话列表/其他设备撤销可放账号子路由；所有变更接口同样执行上述授权规则。非法ID返回统一404/通用错误，不泄露他人资源是否存在。

## 七、AI：配置后可用，默认不调用

### 能力与用户体验

前端始终有随行助手入口。未配置模型时显示“AI尚未配置，可手动调整行程”，不返回伪聊天、不要求用户在网页填写厂商密钥。

适配层先支持一种OpenAI兼容协议的严格子集：服务器配置供应商、模型、可信固定端点、密钥、超时、token预算和用户额度。能力启用但关键环境变量缺失时启动失败；能力关闭时无需密钥。

有真实数据源前，仅处理用户陈述的条件和已核验地点库；不能冒称实时天气、当日路况、票务库存或自动预约成功。自动地图/检索工具未实现就清晰标为不可用。

### 提案闭环

1. 用户明确发起，服务端最小化抽取此旅程的当前状态、约束、允许披露线索和可靠候选；聊天不携带其他用户内容或未解锁结局。
2. 第三方内容、用户消息和模型输出全部当不可信输入。模型不得获得系统命令、文件访问、数据库连接或通用网络代理工具。
3. 使用固定输出schema：说明、引用sourceIds、建议操作、不确定性、预计影响。无结构化输出时安全拒绝，不能用eval解析。
4. 允许操作仅包括替换/跳过未完成停靠点、调整未开始日期与时间预算、插入已核验短支线；禁止修改owner/role、源文档、证据级别、已完成观察、来源核验标记。
5. 服务端再次检查Place/Quest ID、地理走向、步行预算、重复/冲突、引用存在、闭馆/未知状态以及当前revision。模型不能自行认定某地点READY。
6. 展示提案差异，点击确认才创建检查点并整体应用。中途出错全部回滚；提案生成后旅程有更新则要求重新生成/复核。
7. 用户取消、超时、限额、提供方错误都有明确状态；自动重试有上限且不自动应用，避免重复收费与请求风暴。

### 外连与注入防护

- 首版只向服务端预先允许的HTTPS厂商端点发请求，端口443；用户和模型不能填写URL。
- 如实施自定义端点，管理员配置也必须校验：协议/主机/端口允许名单；解析全部A/AAAA；拒绝回环、私网、链路本地、组播、保留段及用户要求的9/8、11/8、21/8、30/8，规范化IPv4映射IPv6。
- 连接固定到已验证IP，同时保持正确TLS主机名/SNI验证；禁止自动重定向，任何允许的跳转重新完整校验。限制请求/响应体、连接时间、并发和重试。
- 不使用shell拼接、不执行模型代码、不开放任意文件路径，不让引用中的指令覆盖系统业务规则。
- AI原始响应默认不全量写日志；仅保存必要提案与用户选择的对话，提供删除入口。输出按文本/安全组件渲染，不使用未清洗HTML。

## 八、免费 IP HTTPS 与原服务兼容

### 已核实的外部依据

- [2026-01-15 IP证书正式开放公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/)已读：IPv4/IPv6均支持，必须使用 `shortlived` profile，精确有效期160小时（6天16小时），不是90天。
- [2026-03-11 Certbot支持公告](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)已读：IP证书支持从Certbot5.3开始，webroot方式至少需要5.4；文中当时nginx/apache插件不支持自动安装IP证书。优先 `certonly` 获取、明确证书路径与成功后重载钩子，实施时复核所选客户端当前文档。
- [Challenge Types](https://letsencrypt.org/docs/challenge-types/)已读取：IP支持HTTP-01（公网TCP80）和TLS-ALPN-01（443且客户端支持），DNS-01不用于IP证书。
- 现有Certbot2.9.0低于该webroot支持版本。证书本身免费，但自动续期和公网实际证书监测是上线必需；现有服务器、网络和日后模型费用另算，不承诺全部运营零成本。

### 上线顺序

1. 经权限批准检查真实Nginx完整配置、证书清单、服务账户权限、IP归属/稳定性和现有端口用途，不打印私钥或环境秘密。
2. 不替换现有全局default站点。为确认属于本机的IP建立精准入口，保留其他域名与webhook原有路由。80仅增加ACME专用目录与必要跳转/迁移入口。
3. 优先webroot HTTP-01，避免停止现有80/443服务抢占端口。若80公网不可达，只有客户端和现有TLS路由明确支持时才考虑TLS-ALPN-01，不靠DNS-01替代。
4. 现有Certbot2.9.0不作为IP签发已就绪；先核实新版本支持，再采用独立安装环境，不破坏其他站点的证书定时任务/配置。安装前保存已有证书工具配置，密钥备份保持私有。
5. 在staging完成IP验证与续期流程，再切正式CA。staging证书不可当浏览器可信证书交付。
6. 每日多次运行受支持客户端的标准renew定时器，按其有效期/续期窗口逻辑工作，不自行盲目强制重签。续期成功后先Nginx配置检查再重载，失败保留现有有效配置。
7. 设置到期检查与systemd失败状态；证书剩余不足48小时或持续续期失败进入高优先告警。没有外部通知通道时只称“本机监测”，不虚称主动通知已配置。
8. 公网验证IP SAN、信任链、HTTPS API、静态资源无混合内容、其他站点与hook仍正常；验证完后才开放账号。
9. 证书失败时停止公网账号上线；不降级发送口令到HTTP，不让用户点击忽略证书警告。

### HTTP 到 HTTPS 的数据迁移

localStorage/IndexedDB按scheme+host+port隔离，即使同一个IP，旧HTTP的8802端口与新HTTPS443也不是一个存档空间。

- 先在旧入口部署不含账号业务的迁移提示和旧档导出功能，保留明确 `/migration` 入口及有限迁移窗口。
- 所有HTTP `/api/` 私有路径直接拒绝；不通过307/308重放含口令的POST到HTTPS，也不在HTTP接收登录表单。
- 用户在旧原点导出JSON，再在新站点验证、预览、另存；HTTPS页面不读取HTTP存储，不用不可信 `postMessage` 绕过同源规则。
- 旧HTTP内容没有传输完整性保障，因此导出文件仍按不可信导入处理，绝不承载登录/邀请/恢复凭据。
- HTTP普通GET页面完成过渡后跳到固定可信HTTPS origin；ACME、旧档迁移及现有hook分别配置，不能一个全局跳转破坏它们。
- hook保留签名验证且与用户后端隔离；切换hook到HTTPS须同步验证调用方配置，不能默默改变现有自动部署行为。

## 九、数据目录、运维与恢复

建议正式目录由部署配置固定为 `/var/lib/tripplane/`，静态构建不包含数据库、备份、环境文件。应用账户最小权限；数据库目录0700/敏感文件0600；实际更改系统目录须经过工具权限批准。

- SQLite启用外键、WAL、合理busy timeout；短事务，SQL值全部绑定，动态排序/列名使用静态白名单。
- 后端环境配置与证书私钥只在服务器受限位置；日志不输出session、邀请码、恢复码、模型密钥、完整用户笔记或定位。
- Nginx配置CSP、nosniff、反嵌入/Referrer Policy；同源资源优先；开发WebSocket/CSP配置不得带入生产。
- 禁用非必要上传；若后续加入图片，再独立设计扩展/MIME/magic/大小/配额/UUID/不可执行存储，本轮不预留可任意上传的通用接口。
- 数据库迁移有schema版本、校验和和事务；迁移前备份，版本不兼容即停止服务启动，不自动猜测字段。
- 备份使用SQLite在线备份机制或受控停写一致快照，不能在写入过程中直接只复制主db而丢WAL。
- 首版保留7份日备份及4份周备份，至少做一次隔离目录恢复演练；备份有完整性校验和最小权限，不放Web目录。
- 整库恢复可能回滚密码、停用状态和已兑换邀请码。正式恢复后先使全部会话、未使用邀请/重置凭据失效，审核用户有效状态，受影响账号经安全恢复流程重置口令后再开放；不能让旧备份复活已撤销访问权。
- 只有同机备份不能抵御整机/磁盘损坏。暂无异机存储时如实注明，提供用户JSON导出；后续选定备份目标才承诺灾备。
- 备份加密需使用标准工具和环境提供的密钥/公钥，不能自制加密或把密钥同库打包。
- 定时任务随部署systemd配置管理，不创建IDE自动化重复执行服务操作。

## 十一、并行审查后的必须补充项

以下优先于前文的简化流程描述，是实施验收的一部分，不另开版本。

1. **恢复代次**：服务器维护CSPRNG生成的 `storageEpoch`，普通应用重启不改变，整库恢复/重建时强制重新生成，不能从旧备份还原。同服务器的本机队列、所有变更和AI提案绑定 `storageEpoch + intendedUserId + journeyId + baseRevision`。不匹配返回冲突并暂停自动同步，用户对照后另存或重新基准，防止revision回退造成旧写入重新合法。恢复操作本身应受控、可审计，并完成第九节的身份失效处理。
2. **切换账号与多个标签页**：切号/退出先暂停旧同步队列、取消在途请求、清空私有内存；本地身份代次递增，旧请求即使延迟返回也丢弃。用跨标签通知同步切换。服务端写入请求的 `intendedUserId` 必须与会话相符，它只用于一致性检查，不代替会话授权；防止用户A的离线“新建”请求带用户B的cookie上传。离线退出只保证本机退出，远端撤销须联网完成或会话到期，不能宣称即时撤销所有设备。
3. **事务完整性**：AI确认只提交proposalId、expectedRevision、operationId、storageEpoch，不接收客户端改写后的模型操作集合。一次SQLite事务中完成二次归属验证、未删除/未过期检查、写入恢复前检查点、版本条件更新、提案已应用状态与幂等结果。幂等重放也重新检查当前归属和用户状态。同一opId不同请求拒绝；删除后的更新严禁upsert，保留墓碑直至明确清除策略允许，避免离线队列复活。
4. **缓存与同IP边界**：所有API状态码（含401/500/导出）均no-store，SW不对API错误回退HTML；Nginx不缓存私有响应。cookie不按端口隔离，部署前必须盘点同一IP上其他HTTPS服务：不同端口不是账户安全隔离方案。存在不可信同IP服务时不能开放该IP账号cookie，保留本机模式并报告真实阻断。裸IP不能依赖浏览器HSTS，显式HTTPS入口及HTTP敏感请求拒绝不可省略。
5. **续期必须验证真正生效**：至少每日两次检查续期，尊重客户端续期逻辑；成功签发后配置校验、重载，再独立检查公网实际呈现的证书序列号/有效期/链。证书文件更新或计时器显示成功都不等于浏览器收到新证书。48h/24h分级告警，失败不降级HTTP，不反复强制签发触发限额。
6. **发布流程兼容**：只读审计发现现有 `scripts/deploy-tripplane.sh` 会覆盖仓库Nginx模板，`scripts/pull-and-deploy.sh` 有dirty工作树保护和破坏性Git操作；本轮不执行。实施需同步更新受控发布模板，改为经验证的构建产物切换，保留其他站点和hook。再次正常发布后必须仍为HTTPS、私有HTTP接口仍拒绝。未获明确授权不执行破坏性Git命令，不把本次未提交改动交给旧自动拉取流程覆盖。
7. **具体失败注入用例**：测试A离线创建→B登录→旧响应返回；两设备同revision并发确认只有一个成功；保存事务中断不得留下半个检查点；恢复旧数据库后旧epoch请求全部拒绝；旧邀请码/session不复活；证书重载失败可检测；再次发布不退回HTTP。

审查分工：`architecture-audit` 提供入口、存档、发布脚本证据；`security-review` 提供权限、离线身份、恢复代次和证书失效边界。主方案选Express5并保留现有Zod，替代评审建议中的Fastify；两者不混装，理由是单体JSON API规模小、减少schema桥接，安全能力按本文显式实现，不依赖框架默认。IndexedDB采用Dexie统一事务封装；新模块使用TypeScript并增加类型检查，旧JS渐进接入。依赖版本在实施时选定受支持且审计通过的版本，锁文件来源使用可信HTTPS源，不无故重写未修改依赖。

本轮交付仅为上述设计与证据边界；实施结果必须用真实命令、API测试、浏览器检查和公网验证更新，不提前打勾。

# 山河行记 · 路线页地区分组与展示修复需求

创建日期：2026-09-29；来源：用户2026-09-29展示方式问卷确认 +「新增4站插入对应地区分组」补充要求。
对应计划：[PLAN_20260929_路线页地区分组与展示修复.md](PLAN_20260929_路线页地区分组与展示修复.md)

## 用户诉求

用户反馈：上次秋日四站更新后，路线页被按日期的内容占据，历史地点卡不易找到；首页「这一站，听什么故事？」只固定显示3张，其余旧地点看不到。经确认，具体要求为：

1. 路线页「按11天行程（DAY 1–11）」时间轴：保留为可切换的「按行程」视图，默认改为按地区分组；仍可通过按钮切回11天时间轴查看。
2. 「9/30–10/3四天专题」（当前路线页置顶）：从路线页移除，不再显示；四天行程数据保留，可在首页保留入口。
3. 首页「这一站，听什么故事？」：增加显示数量（如6张），保留主题筛选，首页多展示一些地点卡。
4. 补充要求：秋日新增的4站（铜川博物馆、壶口、南泥湾、宝塔山）插入到对应地区分组里。

## 输入

- 现有代码：`src/shanhe/App.tsx`（首页／路线页渲染）、`src/shanhe/styles.css`、`shared/content.js`（`places`、`regions`、`themes`、`days`、`autumnDays`、`guanzhongStoryIds`）、`src/shanhe/random-explore.js`。
- 现有测试：`tests/adventures.spec.ts`、`tests/random-explore.spec.ts`、`tests/mobile.spec.ts`、`tests/content.test.js`。
- 现有约束：32地点／96章／309项行动，原行动ID与顺序冻结；秋日新增四地追加在原列表后。

## 目标

- 路线页默认按地区分组展示全部地点，历史卡片与新卡片同样可见、同组同列。
- 11天时间轴仍可查看，不删除、不改变 `#day-N` 锚点语义。
- 路线页不再被四天专题遮挡；四天专题只在首页作为入口保留。
- 首页精选展示6张卡，主题筛选继续生效。
- 展示层改动不影响存档、同步、随机探索与AI提案语义。

## 关键口径

- 分组依据 `place.region`，顺序沿用共享 `regions` 数组；空组不渲染；组内复用既有 `renderPlaceCard` 与 `.place-grid`。
- 秋日新增4站不作特殊置顶：铜川博物馆归入「铜川」，壶口瀑布（陕西侧）、南泥湾（湿地与水土）、宝塔山（古塔与地形）归入「延安·宜川」。
- 有筛选条件（搜索／主题／地区非默认）时维持现状的平铺结果，不渲染视图切换按钮，避免隐藏搜索结果。
- 切换控件：`role="group" aria-label="路线展示方式"`，按钮名「按地区」「按行程」，`aria-pressed`；不得出现「全部」，以免与「路线主题」分组冲突。
- 首页精选6个固定id须与 `guanzhongStoryIds`（茂陵、法门寺、乾陵、懿德太子墓）无交集，且仍包含耀州窑（既有用例依赖）。
- 只改渲染层：不调整 `raw` 顺序、不新增地点、不重排 `questIds`、不改行动ID与旧存档迁移语义。
- 本次不发布，不改Nginx／端口／8802／443；浏览器用例受 `No usable sandbox` 阻断时如实说明。

## 验收标准

1. 路线页默认展示按地区分组的全部地点卡；点击「按行程」可切换到11天时间轴，`#day-N` 与日期标签不变。
2. 路线页不存在9/30–10/3四天专题区块；首页该区块仍然存在且可跳到各日期。
3. 首页「这一站，听什么故事？」在「随心看看」下显示6张卡；切换主题后按该主题取前6张。
4. 秋日4站在路线页地区视图中分别出现在「铜川」「延安·宜川」组内，卡片保留原有「已有场所线索／入口待核验」语义。
5. `npm run typecheck`、`npm test`、`npm run build` 通过；`tests/adventures.spec.ts` 中依赖旧默认视图与路线页专题的断言已同步修正，未放宽既有兼容测试。
6. 360–430px无横向溢出，触控区44–48px（沿用例外样式基线）；如浏览器无法启动，如实记录为环境阻断。

## 风险

- 路线页默认视图变更会影响依赖 `#day-1` 的既有浏览器用例，必须同步修正而不是删除覆盖。
- 首页卡片增多可能造成同页重复可访问名（如与关中四地专题重复），影响无障碍与严格模式定位，须避开。
- 移动端分组后的横向滚动／宽度若处理不当会产生横向溢出，需沿用既有响应式规则。
- 浏览器沙箱不可用，手机端到端无法给出运行证据，仅能以类型检查、Node测试、构建与静态复核为证。
